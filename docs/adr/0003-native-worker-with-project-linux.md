# 原生 Worker 为主，Linux 作为项目兼容插件

方案500：固定官方 Worker 的会话与模型 Agent 运行在 WKWebView 中，由 Swift 网关管理唯一的原生项目工作区和耐久状态；只有启用 Linux 插件的项目才在打开时异步准备无 JIT guest，需要 Linux 的工具等真实 ready 后自动执行一次。选择它，是因为冷启动 Linux 前用户已能打开会话、读写项目并恢复状态，同时保留 Linux shell、子进程和依赖兼容。

用户于 2026-10-06 确认此决定，含 `none` 共享模式与“事后检测并转为冲突”的隔离语义。它取代 [ADR 0001](0001-local-linux-emulation.md) 中“官方 Harness 本身先在完整 Linux 内运行”的部分；无 JIT Linux 模拟仍是 Linux 执行路径。证据是独立 iPad 研究 App 上的有界检查：两种 9P 模式各 23 项 Worker/网关协作 + 9 项进程恢复，以及 `none` 模式真实模型小闭环 8/8（官方 Agent 带版本修改文件，Linux 精确运行测试后返回最终结果），见 [Worker/Swift/Linux 报告](../research/plan500-worker-gateway.md)。完整 G0–G7 均未通过。

## 决定

- **权威工作区**：项目唯一内容在 App 原生工作区，Linux 经 9P 挂载同一目录。不以 Worker VFS 副本批量覆盖宿主。官方会话只检查点 `/dsh/home`，项目和草稿各自耐久保存。
- **共享模式选 `none`**：原生侧看到普通 mode 和 symlink，原生读写、Git 与 diff 直接可用；真实模型闭环也只在此模式通过。代价是 guest 不能在共享工作区创建 FIFO/Unix socket，需要它们的工具改用 guest 私有路径，做不到就声明为不支持。`mapped-xattr` 不选：宿主上的 mode/symlink 与 guest 不等价，会破坏原生侧对项目的理解。
- **统一写者合同**：原生修改和 Linux 命令共用一个耐久写租约。Linux 写入期间原生修改保存为草稿；取消只在确认写者停止后释放租约；冲突保留草稿字节；断连保持写者未知，不重放命令。
- **隔离语义**：租约协调的是协作写者，不防恶意 guest 代码。同 uid 经 `/proc`、SCM_RIGHTS 的绕过写入和原生 CAS 的 TOCTOU 采用“事后检测并转为冲突”，不承诺实时阻止。用独立 uid 或更强隔离加固留作后续，不是首个正式范围的前提。
- **能力声明**：项目类型、工具和插件逐项标为 `native`、`linux` 或 `unsupported`。安装脚本、整段 shell、管道和依赖外部命令的 hook 属于 `linux`，任务开始前选定执行路径，已有副作用后不换执行器重跑。
- **Linux 生命周期**：每个 App 进程最多启动一次 QEMU；VM 退出沿用诊断加关闭重开，不假定同进程可重启。“后台准备”只指前台期间的异步准备。
- **交付与数据**：[ADR 0002](0002-runtime-ships-inside-ipa.md) 继续适用：运行时随 IPA 整体交付，系统内容只读，用户数据不被覆盖。旧用户盘不直接挂作新工作区；迁移走隔离备份、逐文件核验，并保留旧 App 与旧用户盘作回退。

## 首个正式兼容范围的前置关口

接受方向不等于产品可交付。下列关口由 #17 起的实现关闭，任一项不通过就收紧兼容范围，不跳过：

1. **G2 耐久数据**：活动写者崩溃、注入未完成写入、损坏日志下只提交完整记录、保留可恢复副本；明确会话与项目之间不是跨文件事务时的恢复规则。
2. **G1 模型路径**：增量流式交付、取消、认证与网络错误；当前 SSE 是缓冲交付。
3. **G3/G5 Git 与 hook**：首个范围内的 Git 操作在原生与 Linux 两侧一致；阻止型 hook 在提交前执行，失败无提交或远端副作用。
4. **官方工具等价**：研究只注册了三个工具。正式版本要把首个范围内的 fs、编辑、搜索与 Git 工具接入原生工作区，不能经继承 VFS 或 subagent 绕过。
5. **G7 迁移与回退**：从隔离备份迁入，逐文件核验，失败可回到旧交付包。
6. **私有接口条件**：Darwin 9P backend 依赖私有 `pthread_fchdir_np`。现有正式 IPA 已编入该 backend 并弱链接此符号；正式实现须在启动时检测缺失，并对 Linux 插件给出明确的不可用，原生核心不受影响。

性能、内存、后台恢复、watcher/HMR 和 G6 插件生命周期须实测并记录，但只影响兼容范围大小，不阻断方向。

## Considered Options

- **Harness 继续全部运行在 Linux 内**：已有维护路线和回退包，不需改写官方 provider；但打开项目、进入会话都要等 VM，Linux 不可用时什么也做不了。
- **全部工具改写为原生**：不需要 guest，但做不到用户要求的 Linux shell、子进程和项目依赖兼容。
- **原生 Worker 加项目 Linux 插件**（选定）：接缝已在 iPad 上跑通真实模型闭环。代价是要维护官方工具 provider 适配、双域写者合同和数据恢复。
- **共享模式 `mapped-xattr`**：guest 内文件类型更完整，但宿主上 mode/symlink 变成 xattr 表示，与原生权威工作区冲突。

## Consequences

- 一次 Node 测试通过不代表完整开发项目兼容；兼容范围以逐项能力声明和验收为准。
- 官方 Worker 版本升级要同时复验工具注册适配、Zod/WebKit 兼容层和写者合同。
- 恶意或失控的 guest 进程可以绕过租约写项目文件，只会在释放时被发现并转为冲突。威胁模型变化时须重新评估 uid 隔离。
- 本决定结束 #32 的架构关口，#17 据此实现。生效本身不触发正式 App 安装、用户盘迁移或新设备安装。
