# 运行时随 IPA 整体交付，系统盘与用户盘分离

每个 IPA 内置一个完整的运行时版本：小 initramfs，加一张从 App bundle 直接只读挂载的未压缩 ext4 系统盘。用户的项目、依赖与会话放在独立的用户盘里。用户盘首次启动时由种子创建，之后永不覆盖。

升级、回滚都只靠覆盖安装同签名身份、同 bundle ID 的 IPA。设备上不运行 `apt upgrade`，也不在首次启动时下载运行时。

这样选，是为了最快得到一个可复现、可整体验收的版本：每个发布对应一份构建清单和一个对应源码包，重装 App 只替换系统内容，不覆盖用户盘；这不能代替损坏用户数据的救援。

## Considered Options

- **首次启动下载运行时，或在设备上按包升级。** IPA 更小，但会引入下载失败、部分升级和设备之间状态不一致的问题，还会让源码义务随设备上的状态变化。
- **单盘，或把整个系统放进 initramfs**（原型的做法）。冷启动要先解包约 679 MiB，系统与用户数据也无法分开升级。
- **erofs 或 squashfs 压缩系统盘。** 体积更小，但未经验证；IPA 的 zip 已经提供传输压缩，于是沿用原型已验证的 ext4。

## Consequences

- 原决策预估 IPA 约 250–300 MB，安装后约 0.8–1 GB，不作为验收结果。后续采用 #6 的 ≤350 MB IPA、≤1.2 GB 应用本体预算；最新无签名 App 逻辑文件总量约 1.199 GB，设备实际安装占用仍待测，见 [存储与工具验收](../validation/ipad-storage-tools.md)。
- 任何上游变化（dsh、Node、UTM/QEMU、Debian 快照）都要出新 IPA，并跑固定验收清单。
- 换签名身份或 bundle ID 等于换了新容器，数据只能通过用户数据备份迁移。
- 用户盘带布局版本；遇到比自己新的布局时进入救援模式，绝不改动磁盘。
