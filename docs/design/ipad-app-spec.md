# 官方 Harness 的 iPad App 适配 Spec

状态：2026-10-04，M1–M3 核心实现已进入 main，工具与存储设置已补代码；真机验收仍待集中完成。本文固定应用体验并接入已关闭的首版范围、工作区与插件决策；实现状态见任务表，验收结论见验证记录。

追踪入口：[规格：官方 Harness 的 iPad 全屏 App 适配与可安装版本](https://github.com/lvivvde/deepseek-harness-ipad/issues/15)。

目标：安装一个自签 IPA，打开就是完整的官方 Harness。项目、会话和工具执行都属于 iPad 内的同一个 Linux 执行环境。用户不需要先打开诊断外壳、导入 guest，再打开一个可以点外侧关闭的网页弹窗。

## 1. 已确认与待定范围

| 类别 | 约束或来源 |
| --- | --- |
| 本会话确认 | 官方界面直接作为整个 App 的主界面；沿用工作区侧栏、会话、输入框和已有工具呈现，不另做聊天工作台。 |
| 本会话确认 | Git 获取的项目有持久存放位置；切换工作区、会话和关闭辅助窗口不停止 Harness，不重新启动 Linux。 |
| 架构基线 | Swift 原生宿主、WKWebView 官方界面、无 JIT aarch64 Linux、官方 Node/dsh；工具本地执行，允许联网调用模型。 |
| [原型结论](https://github.com/lvivvde/deepseek-harness-ipad/issues/11) | 核心链路真机通过。官方界面、API Key、模型调用与本地 Node 测试已验收；产品体验和完整 Git 闭环仍要实现。 |
| [运行时交付决策](https://github.com/lvivvde/deepseek-harness-ipad/issues/12) | IPA 内置小 initramfs、只读 ext4 系统盘和用户盘种子；用户盘挂载 `/root`，创建后永不被应用升级覆盖。 |
| 已定 | 首版项目与工具清单、设备覆盖、容量与性能预算由 [首版范围](https://github.com/lvivvde/deepseek-harness-ipad/issues/6) 收敛。项目导入、Files 交换和 Git 凭据由 [工作区决策](https://github.com/lvivvde/deepseek-harness-ipad/issues/7) 收敛。 |

首版支持 Node.js / TypeScript 的 S 档项目与 L1–L3 形态，承诺 npm；系统盘预装工具以 #6 为准。最低目标为 iPadOS 26、M 系列、8 GB 内存，当前仅 M4 16 GB 有真机记录。guest 固定 2 GiB、无 swap；用户盘默认 8 GiB、用户手动在线扩到 64 GiB、不缩小、不自动扩容，宿主剩余空间低于 2 GiB 时提醒并拒绝扩容。性能和体量预算按 #6 集中实测。

## 2. 界面设计

视觉基准是用户提供的官方桌面 App 截图：左侧工作区与会话，右侧完整官方内容区。复用部署版本的真实前端，不制作外观相似但没有真实行为的替代界面。

### 主界面

- 官方页面铺满 App 内容区域，处理 iPad safe area；不显示原生导航标题、地址栏、“打开 Harness”按钮或外围诊断卡片。
- 主界面不是 sheet，也没有下拉关闭或点外侧关闭操作。页面和 VM 都不由辅助窗口的显示状态决定是否存在。
- 保留官方侧栏、工作区选择、会话恢复、插件入口、权限选择和模型选择。桌面的窗口控制不复制到 iPad。
- 窄窗口按实际可用宽度折叠官方侧栏；横屏、竖屏及系统分屏中输入框和发送/停止按钮始终可操作。优先沿用上游响应式行为，缺口用最小适配补齐。
- 软件键盘不能遮住输入框或当前操作；外接键盘、中文输入法组合输入与触控停止生成分别验收。适配不更改官方会话与工具语义。

### 启动、重连与辅助入口

| 状态 | 用户看到的内容 | 行为 |
| --- | --- | --- |
| 首次启动 / 冷启动 | 同一 App 内的简洁启动页：准备数据、启动环境、启动 Harness；慢时显示当前阶段与诊断入口 | 自动完成初始化；无需选择镜像或手动启动。没有实测数据时不显示虚构百分比或倒计时。 |
| 已就绪 | 完整官方界面 | 页面可绘制后移除启动页；避免先露出空白页面。 |
| 页面连接中断，VM 仍在 | 保留当前页面，显示轻量“正在重新连接”提示；需重载时先显示恢复页 | 先恢复连接，再恢复官方工作区和会话；不因一次 HTTP 超时重启 VM。 |
| 系统终止 App 后重新打开 | 启动页，明确“正在恢复工作区” | 冷启动并复用用户盘；不承诺保存被中断的整段流式回答。 |
| 无法恢复 | 简洁故障页：原因、适用的重试操作、诊断与数据救援入口 | 不自动格式化、删除用户盘；不能恢复时不无限显示加载动画。 |

设置、文件选择、授权窗口与诊断可以使用辅助窗口，但关闭它们只影响该窗口。诊断不作为默认首页。若官方设置没有宿主能力入口，增加一个收敛的“iPad 应用设置”入口，承载版本、用户数据备份/恢复、开源许可与诊断；不再增加一层主导航。

外链与授权窗口沿用上游认证流程，并明确区分主 Harness 页面和子窗口；取消授权或关闭外链不会关闭主页面。官方账号登录的兼容承诺由 [账号与插件决策](https://github.com/lvivvde/deepseek-harness-ipad/issues/8) 确定。

## 3. 项目与 Git 的承载

应用的数据容器保存用户盘，Linux 内 `/root` 保存项目、依赖、Harness 状态与缓存。原生层不再创建另一份用于执行的项目副本。

按已定工作区决策，Git 项目集中在 `/root/projects/<项目名>`，并登记到官方工作区列表。Files 使用 tar+SHA256 导入/导出；已有登记路径不能被悄悄移动。凭据由用户在终端提示中输入，不经对话或远端 URL。

项目操作契约：

1. 获取项目时，Git 在 guest 内执行，结果落在用户盘；成功后通过官方工作区登记机制打开该目录。先核查上游是否已有克隆入口，缺失时在工作区入口增加最小适配，不额外开发一整套 Git 客户端。
2. 新建项目、打开已有项目与 Git 克隆得到的项目使用相同的工作区机制。项目是目录，不依赖某个会话是否存在。
3. 切换工作区只切换官方工作区上下文；不卸载磁盘、不重启 VM、不终止其他会话中的任务。沿用官方任务规则，不额外承诺并发能力。
4. shell、依赖安装、测试和 Git 操作都以该工作区为上下文；官方沙箱权限仍生效，不为方便克隆而给所有会话全盘写权限。
5. 失败或取消的克隆不显示为成功工作区；重试不覆盖已有同名项目。临时目录与用户已有项目明确区分。
6. Git 提交身份、私有仓库认证、推送授权及凭据存储遵循工作区决策；凭据不写入诊断、构建清单或仓库。

首版用固定 S 档 Node/TypeScript 仓库验收获取、依赖安装、模型修改、差异审阅、测试和本地 Git 提交。完整本地开发闭环还必须在用户授权的测试远端完成推送；只有 clone 和本地 commit 通过时，明确记录推送尚未通过。

Files 作为导入、导出与备份入口。首个版本不宣称外部 Files 目录与 ext4 工作区实时双向映射；具体支持方式由工作区决策确定。

## 4. 运行环境与页面的生命周期

关键不变量：同一 App 进程只有一个运行环境所有者；主页面、工作区和辅助窗口不持有 VM 的启停权。启动请求可重复调用，但并发请求共享同一启动过程，不能创建第二个 QEMU。

页面状态与运行环境状态分别管理：页面故障不等于 VM 退出，HTTP 超时不等于磁盘失败。进入后台不主动停止 Harness；申请有限后台时间做必要同步，不承诺后台一直执行模型或工具。

回到前台后的恢复顺序：

1. 检查运行环境、控制通道与本机页面连接，保留仍工作的路径。
2. 页面进程退出而 guest 正常：重新加载真实官方页面，重新完成所需认证并恢复工作区/会话，不重启 Linux。
3. 内部连接失效而 guest 正常：修复控制连接及端口转发，再重连页面。失败后展示可操作的恢复状态；不能仅把失败隐藏为普通页面加载。
4. guest 尚在而 Harness 退出：在能确认前一实例已退出且磁盘可写后重新启动 Harness，不创建第二个实例。
5. QEMU 真正退出：现有桥接未证明同进程内可安全重启。首个版本显示“请关闭并重新打开应用以恢复”，保留用户盘；在同进程重启验证通过前，不提供会调用旧桥接再次初始化的假重试按钮。

首个版本单窗口、单 VM。未来多窗口可共享应用级运行环境，但不作为本次交付的前置任务。

## 5. 实现设计

以下是拟实现的模块职责，不声称原型已经有这些 interface。

| Module | Interface 与不变量 | 隐藏的实现 |
| --- | --- | --- |
| 应用级运行环境 | 幂等 `ensureRunning()`、前台恢复、可观察状态与恢复动作；视图销毁不停止环境 | QEMU 启动、磁盘准备、启动标记、控制通道、Harness 存活探测、端口转发、就绪判定。 |
| 官方页面宿主 | 接收真实就绪入口和连接状态；提供页面恢复结果，不调用 VM 启停 | WKWebView、官方鉴权、页面进程恢复、键盘与触控适配、外链/子窗口路由。 |
| 用户数据管理 | 首次创建、备份/恢复、版本检查；既有用户盘永不被安装或初始化覆盖 | ext4 种子、空间检查、异常恢复、归档校验与 Files 交换。备份时协调写入者，不复制正在写入的 raw 盘。 |
| 运行时构建 | 一份固定输入生成对应 IPA 资源、清单与源码资料 | 小 initramfs、只读系统盘、内核模块、Node/dsh、工具清单、依赖与许可收集。 |

不为这些职责提前制造只有一个实现的通用 provider 层。先实现真实流程，在故障与状态变化的位置建立可测试的 seam。

控制通道优先验证管道或预先创建的 socketpair，避免只依赖挂起期间失效的 TCP 监听。具体采用方式必须以当前嵌入式 QEMU 的可用能力和真机恢复结果为准；页面 hostfwd 单独验证。运行时版本、通道重连和页面恢复都需要真实错误结果，不能用假页面判定成功。

### 原型可复用与需要替换的部分

- 可复用验证过的 QEMU 加载方向、官方 dsh 启动参数、认证入口转换、官方页面就绪判定与触控停止生成修正；每项在新布局下重新验收。
- 原型 `PrototypeView` 使用 `.sheet` 显示 `HarnessWebView`，关闭它会移除页面；这段代码本身没有停止 VM 的调用。不能把“网页消失”直接归因为“Linux 被关掉”。正式主界面移除该呈现方式。
- 原型 `PrototypeVM.start()` 有单次启动保护，`QemuBridge.m` 明确要求 QEMU 返回后重开 App；产品的恢复策略必须遵守这项限制，直到新的实现有证据支持安全重启。
- `PrototypeCommand.txt` 是实验 mailbox，不作为产品控制协议。正式控制入口要有请求结果与超时，诊断日志默认脱敏。
- 正式工程使用独立 bundle ID 与数据容器。按运行时交付决策，不读取、迁移或覆盖现有原型 App 的项目与磁盘。

## 6. 首个可安装版本的验收

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| A1 | 安装后首次打开 | 不导入 guest、不下载运行时、不点启动；自动进入真实官方全屏界面，原型容器不受影响。 |
| A2 | 点页面外沿、关闭侧栏/子窗口、切换工作区/会话 | 主页面不被关闭；运行环境启动次数不增加。 |
| A3 | 创建与获取项目 | 新建目录、公开仓库克隆并登记到官方工作区；文件实际位于 guest 用户盘，失败不产生假成功项。 |
| A4 | 小型项目开发 | 官方 API Key 配置后，模型修改真实文件、运行依赖安装与测试；可查看差异并创建本地 Git 提交，命令与退出码留有证据。 |
| A5 | 推送 | 在用户授权的测试远端完成推送；未提供测试远端时列为未验收，不扩大 A4 的结论。 |
| A6 | 重启与同身份覆盖安装 | 项目、Git 历史、会话和配置仍在；不重复创建或覆盖用户盘。 |
| A7 | 页面进程退出 / 短暂后台 | 页面可重连，VM 不重启；工作区和会话可以继续操作。 |
| A8 | 长时间后台 / 整个 App 被终止 | 分别实测连接恢复和冷启动恢复；失败有明确救援操作，不丢失已落盘项目，不宣称后台永久保活。 |
| A9 | 触控与键盘 | 竖横屏、窄窗口、软件/外接键盘、中文组合输入、停止生成均可用；不出现窗口套窗口或诊断外壳首页。 |
| A10 | 用户数据与故障 | 导出/恢复往返通过；磁盘或版本错误进入救援模式，原盘保留。 |
| A11 | 安装与资源 | 提供实际签名/重签安装步骤；实测 IPA、安装占用、首次/再次冷启动和内存。新镜像不沿用原型性能数字作为承诺。 |

停止生成、会话恢复、强杀恢复和 Landlock 探针继续沿用运行时交付决策的固定验收清单。备份包含私密配置，仅在用户选择的目标导出；诊断不导出凭据或完整启动 token。

## 7. 交付顺序

实现任务、依赖和交付物见 [适配实现任务表](ipad-app-implementation.md)。先交付完整主界面与内置运行时的小范围安装版本，再补齐真实项目闭环、恢复与交付验收。讨论票的关闭不是实现通过，也不能代替安装包或真机记录。

正式公开发布继续满足 [执行器归档](https://github.com/lvivvde/deepseek-harness-ipad/issues/13) 和 [许可证判断](https://github.com/lvivvde/deepseek-harness-ipad/issues/14) 的发布条件；这些不阻止本地设计和代码实现。其他会话继续处理决策票时，应把最终约束合入此 Spec，而不是重复开启相同讨论。
